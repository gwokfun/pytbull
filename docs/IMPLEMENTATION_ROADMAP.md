# Linux Auditd威胁检测系统 - 实施路线图

## 文档信息
- **版本**: 1.0
- **日期**: 2026-04-29
- **项目周期**: 12周（开发+部署）+ 持续运维

---

## 1. 项目概述

### 1.1 项目目标
基于Linux auditd框架，构建一个配置驱动、低代码的本地主机威胁检测系统，实现：
- 实时监控系统事件（进程、网络、文件、用户行为）
- 自动检测异常行为和威胁
- 生成告警和可视化报告
- 易于配置和维护

### 1.2 交付成果
1. 完整的威胁检测系统代码
2. 配置文件和规则库
3. 系统文档（设计、安装、配置、运维）
4. Web可视化界面
5. 自动化部署脚本
6. 培训材料

## 2. 实施阶段

### 阶段1: 基础框架开发 (第1-2周)

#### 目标
建立核心架构和数据采集能力

#### 主要任务

**Week 1: 项目初始化和架构搭建**
- [ ] 创建项目目录结构
  ```
  pytbull/
  ├── classes/
  │   ├── threat_detector.py      # 主控制器
  │   ├── config_parser.py        # 配置解析
  │   └── event_queue.py          # 事件队列
  ├── modules/
  │   └── threatDetection.py      # pytbull集成模块
  ├── collectors/
  │   ├── auditd_collector.py     # Auditd采集器
  │   ├── proc_monitor.py         # Proc监控器
  │   └── netlink_monitor.py      # Netlink监控器
  └── conf/threat_detection/      # 配置目录
  ```

- [ ] 实现配置文件解析器
  - INI格式解析（兼容pytbull现有格式）
  - YAML规则解析
  - 配置验证和默认值处理
  - 热加载机制设计

- [ ] 建立数据库Schema
  ```sql
  CREATE TABLE events (
    id INTEGER PRIMARY KEY,
    timestamp TEXT,
    event_type TEXT,
    severity TEXT,
    source TEXT,
    data TEXT,  -- JSON格式
    processed INTEGER DEFAULT 0
  );

  CREATE TABLE alerts (
    id INTEGER PRIMARY KEY,
    timestamp TEXT,
    rule_id TEXT,
    severity TEXT,
    title TEXT,
    message TEXT,
    fields TEXT,  -- JSON格式
    suppressed INTEGER DEFAULT 0
  );

  CREATE TABLE baselines (
    id INTEGER PRIMARY KEY,
    metric_type TEXT,
    metric_key TEXT,
    baseline_value TEXT,
    last_updated TEXT
  );
  ```

**Week 2: 数据采集器开发**
- [ ] 实现Auditd日志采集器
  - 实时tail /var/log/audit/audit.log
  - 解析audit日志格式（key=value pairs）
  - 提取关键字段（syscall, pid, uid, comm等）
  - 处理多行记录（msg字段相同）
  - 断点续传（记录读取位置）

- [ ] 实现Proc文件系统监控器
  - 扫描/proc目录获取进程列表
  - 读取/proc/[pid]/stat获取CPU时间
  - 读取/proc/[pid]/status获取内存使用
  - 读取/proc/[pid]/cmdline获取命令行
  - 构建进程树关系（ppid）

- [ ] 实现Netlink网络监控器
  - 创建netlink socket (NETLINK_INET_DIAG)
  - 获取TCP/UDP连接列表
  - 解析连接状态（ESTABLISHED, LISTEN等）
  - 关联连接到进程（inode匹配）

- [ ] 实现事件队列管理
  - 线程安全的事件队列
  - 生产者-消费者模式
  - 队列满时的处理策略（丢弃或阻塞）

- [ ] 基础日志系统
  - 结构化日志输出（JSON格式）
  - 日志级别控制
  - 日志轮转配置

## 4. 风险与应对

### 4.1 技术风险

**风险1: Auditd日志量过大导致性能问题**
- 影响: 系统资源占用高，影响业务
- 概率: 中
- 应对:
  - 优化audit规则，只采集必要事件
  - 使用异步处理和批量写入
  - 增加处理线程数
  - 必要时使用eBPF替代部分auditd监控

**风险2: 规则误报率高**
- 影响: 告警太多，无法有效使用
- 概率: 高
- 应对:
  - 充分的测试和调优
  - 建立白名单机制
  - 调整阈值
  - 实施告警抑制策略
